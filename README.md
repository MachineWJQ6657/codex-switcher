# Codex Account Deck

Windows 独立桌面账号管理器，使用 **Electron + React + TypeScript**。通过本机 Codex CLI 的官方 App Server 登录、查询额度；通过本地登录文件切换目标客户端账号。

当前版本：**0.4.1**。修复正常任务被历史“中断”状态误触发重启、反复切到同一账号，以及未确认原会话已接收消息就宣告恢复的问题。旧工作流升级后保持暂停，不会自动重新启用。

0.4.0 将自动续接改为在官方客户端执行，修复后台监控停住、指定会话只有手动重启才切号的问题。0.3.1 已修正 Windows 本地界面文件 URL 的构造和导航校验，启动日志保存在用户数据目录的 `startup.log`。主界面从应用根目录定位，路径包含空格、中文或 URL 特殊字符时也会正确编码；加载失败会短暂重试一次。

## 使用

可直接运行 `release/0.4.1/win-unpacked/CodexAccountDeck.exe`，或使用 `release/0.4.1/` 中生成的安装包。开发环境：

```powershell
npm ci
npm run dev
```

首次启动会检测本机 Codex CLI、OpenAI.Codex Windows 桌面应用，以及 `CODEX_HOME`（默认 `%USERPROFILE%\.codex`）。在“客户端设置”中可以更改路径。无需 API Key。

1. 点击“添加账号”，使用官方浏览器登录。可添加多个个人、Plus、Pro、Business、Enterprise 或 Edu 身份。商业身份需要在官方登录页面选择对应工作空间，且管理员已允许 Codex。同一用户在不同工作空间会单独保存。
2. 已登录本机 Codex 时，可点击“导入当前登录”；也可从文件选择器导入 `auth.json`。导入会持有刷新凭据，请仅导入自己的或已获授权使用的账号。
3. 点击“同步全部”。新安装默认每 120 秒轮询，支持 30–3600 秒；界面按分钟更新相对时间，服务变化会主动更新。显示各服务额度桶、主要/次要窗口的**剩余百分比**、重置时间及服务返回的工作空间点数。没有返回的数据保持未知。同步失败时保留上次结果并标记旧数据。旧安装保留原有同步间隔。
4. 完成目标客户端中的任务后，点击“切换并重启”。程序按配置的完整可执行文件路径识别目标，先发出正常关闭请求；若关闭窗口后仍留在后台，4 秒后结束已确认的目标进程树（包括该桌面启动的后端），确认退出后再替换登录缓存并启动。进程身份同时校验 PID 与创建时间，避免只按进程名关闭其他程序。Windows Store 更新后的版本目录会自动重新识别。退出失败时不覆盖凭据。
5. 切换后在目标客户端确认账号。菜单中的“仅切换”适用于目标已退出的情况。“客户端设置 → 恢复上次切换”可恢复切换前状态；恢复前须退出目标客户端。

## 自动工作流

任务在官方 ChatGPT/Codex 客户端内执行。Account Deck 只观察本地会话、查询额度、切换账号及打开原会话，不在自己的 App Server 中执行模型或项目工具。

创建工作流后选择候选账号，可以自动跟随本地任务，或指定一个本地持久化主会话。默认每 15 秒检查，关闭低资源模式时每 5 秒检查。正常运行的任务始终保持原账号和客户端。

### 额度切号

仅当以下条件全部满足才退出官方客户端、切到其他账号并重新打开原会话：

- 曾观察到原线程、原回合在当前账号下运行，随后该回合明确因订阅额度错误失败。
- 重新查询当前账号、指定额度桶，确认额度确实耗尽。历史错误与当前仍有额度的账号不匹配时不切号。
- 没有其他任务仍在运行，且会话持有状态可确认。
- 候选账号额度有效，账号 ID 和实际身份都不同于当前账号。

只显示 0%、普通中断、HTTP 429、旧账号的历史失败都不单独触发重启。没有其他可用账号时等待，不把当前账号重新写入登录文件。两个自动重启之间至少间隔 120 秒，每个来源回合只尝试一次，防止错误循环。

### 中断任务继续

没有运行中的任务时，才考虑最近 24 小时内已停止的中断任务。普通中断只在原会话中提交继续指令，使用当前账号，不改登录文件、不关闭客户端。若刚续接的任务又中断，停止接力并显示原因，不反复干预。

Windows 上独立 App Server 读取历史时，可能把官方客户端未写完的活动回合重建为 `interrupted`。0.4.1 同时只读检查 `thread-writer-locks` 中的 Windows 文件锁；未结束的回合仍被运行进程持有时视为活动任务。其他项目的活动任务也阻止历史任务恢复。状态不明时保持客户端和账号不变。文件锁只能确认会话仍被进程持有，不能证明宿主正在推理；因此在仍被持有且历史不完整时会等待，不抢占该会话。

### 原会话恢复确认

保留原线程 ID、项目目录及来源回合，写入带唯一消息 ID 的队列消息，通过 Windows 系统协议处理器打开 `codex://threads/<id>?hostId=local` 并唤醒同一线程。直接给商店版 exe 传链接不能可靠触发激活，因此通过系统已注册的 `codex://` 处理器投递。

客户端打开后只显示“等待原会话确认”。必须在同一线程中读到 `userMessage.clientId` 与已提交消息 ID 一致，才显示已接收；其他新回合不算恢复成功。未确认时只有限重试唤醒同一消息，不重复换号、重启或追加“继续”。会话卡片显示任务名和项目目录，并提供“打开原会话”按钮，仅导航、不提交消息。

暂停工作流会取消仍在排队的本工具消息，保留用户自己的消息；已在官方客户端执行的任务不受暂停或退出 Account Deck 影响。0.4.0 及之前的工作流升级为暂停状态，账号和配置保留。商业工作空间的模型、项目和工具访问权限继续由官方客户端及组织策略控制。

## 资源占用

默认开启低资源模式。界面关闭硬件加速，仅按分钟刷新相对时间，隐藏时暂停周期 IPC。无需监控时没有工作流计时器。监控时串行查询当前账号与会话状态，仅在需要切号时查询候选账号；临时查询进程结束后立即退出，没有常驻任务执行进程。后台监控不因最小化窗口而停止。前端 React 与图标已打包，不附带完整前端依赖目录。

## 支持范围与限制

- **额度是 Codex 订阅额度**，来自 `account/rateLimits/read`，不是 ChatGPT 网页/移动端所有模型的消息次数。轮询不是服务端实时推送；显示同步时间，超过两轮或查询失败标记旧数据。
- **切换是本地文件兼容适配**：替换所选 `CODEX_HOME/auth.json`。OpenAI 没有公开的第三方接口可热切换已经运行的桌面客户端。支持使用这一登录缓存的客户端；有独立登录存储的版本、系统 keyring 和 ChatGPT 浏览器 Cookie 会话不在文件适配范围内。界面的“本地当前”仅说明缓存匹配，不表示已经向桌面 UI 验证登录成功。
- 目标 `config.toml` 的 `cli_auth_credentials_store` 应为 `"file"`。若显式使用 `"keyring"`、`"auto"` 或 `"ephemeral"`，切换会拒绝执行。可自行改为 `"file"` 后重新登录；本工具不修改目标配置。不提供绕过组织策略的功能。
- 目标配置显式限制工作空间或只允许 API Key 时，切换会拒绝执行。系统或企业级管理配置仍可能造成登录拒绝，最终以客户端和官方服务结果为准。
- API Key 账号不支持 ChatGPT 订阅额度。本工具不保存密码，不提供账号买卖、自动注册或额度绕过功能。
- 当前目标账号的额度查询使用内存中的外部凭据模式，避免在第二个进程刷新目标的 refresh token。若当前 access token 过期，先让目标客户端刷新登录，再同步；其他账号通过隔离的官方登录环境刷新。相同账号若同时被其他工具刷新，可能需要重新授权。
- Windows 优先实现；其他操作系统的客户端发现、关闭和重启需要增加平台适配器。
- 本项目不是 OpenAI 官方产品。安装包未签名。

## 本地数据与恢复

固定的 `%APPDATA%\codex-account-deck\accounts.vault` 保存加密的账号、额度缓存、设置、工作流、操作记录以及一份切换备份，独立于安装目录和版本号。更新或更换安装目录继续使用同一份本地数据，不需要重新添加账号或手工复制配置。若旧版根据产品名选择了其他 userData 目录，首次启动会在新保险库不存在时复制旧的加密保险库，保留旧文件。Windows 使用 Electron `safeStorage` 的 DPAPI，仅创建它的 Windows 用户可正常解密；加密不可用时拒绝保存，不退回明文。不要把保险库或 `auth.json` 放进 Git 或分享给他人。

官方 CLI 与桌面客户端路径在启动和使用时自动重新检测，跟随 Windows Store 版本目录和 CLI 更新。手动指定的自定义程序路径继续保留；需要恢复自动检测时，在设置中点击“重新检测官方安装”。项目目录和候选账号等工作流配置同样存储在本机。登录及额度同步仍会访问 OpenAI 官方服务，不向本项目的服务端上传保险库。

登录及非当前账号同步期间，官方 CLI 需要在 userData 下的 `.sessions/session-*` 隔离目录中临时读取明文登录文件。操作结束清理；异常退出留下的目录在下次启动时清理。CLI 不继承环境中的 OpenAI 凭据，不读取目标的插件和 MCP 配置。额度查询不会创建推理任务。

切换先在加密保险库中保存旧凭据，再原子替换目标文件。写入前重新比对旧文件，检测并发更改。仅保留最近一次备份；如果切换后的凭据又被客户端更新，恢复操作会拒绝覆盖。账号移除只影响本地保险库，不注销目标客户端，也不撤销服务端登录授权。

## 开发和验证

```powershell
npm run build        # TypeScript 检查和前端构建
npm test             # 隔离凭据、同步、切换事务、恢复和 OAuth 完成测试
npm run test:ui      # Electron + Playwright 实际窗口测试（纯合成账号）
node scripts/probe.mjs           # 本机真实 CLI 握手，隔离空账号环境
node scripts/probe.mjs --live    # 只读查询当前登录额度，不刷新或写入目标凭据
npm run pack         # 可直接运行的 Windows 目录包
npm run dist         # Windows NSIS 安装包
```

`test:ui` 使用源码开发模式下的独立测试开关，测试用户目录与真实账号分离；打包版本不接受该开关。截图输出到 `.test-output/`。单元测试中的假凭据与加密器仅在 Node 测试中注入；应用使用真实系统加密。

主要文件：`electron/service.mjs`（账号事务）、`electron/workflow.mjs`（后台监控和官方客户端续接）、`electron/rpc.mjs`（JSON-RPC）、`electron/windows.mjs`（Windows 适配）、`electron/core.mjs`（加密存储与额度归一化）、`src/App.tsx` / `src/WorkflowPanel.tsx`（独立界面）。IPC 返回值不包含 access token、refresh token 或 ID token。渲染进程禁用 Node，启用 sandbox 与 contextIsolation，拒绝未知导航和权限请求。

GitHub Actions 在 Windows 上执行构建、核心测试、实际 Electron 界面测试并生成安装包作为工作流产物。源码仓库不包含 `node_modules`、安装包、登录文件或保险库。

官方接口依据：[Codex App Server](https://learn.chatgpt.com/docs/app-server)（登录及额度）和 [Authentication](https://learn.chatgpt.com/docs/auth)（登录缓存与凭据存储）。接口和桌面登录实现可能随版本变化。
